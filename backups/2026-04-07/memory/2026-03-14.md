## Major Issues Fixed

### 1. Random Canned Responses (21:52 - 22:15)
**Problem:** Bot using `reply-generator-test.ts` random replies instead of contextual Grok  
**Root cause:** Grok model name was wrong (`grok-beta`, `grok-2-latest` all invalid)  
**Solution:** Found correct model: `grok-4-1-fast-reasoning`  
**Fix:** Updated API key + model name + wired to `reply-generator.ts`

### 2. Plagiarism from Real @gork Account (21:48)
**Problem:** Copied exact tweets from real Gork ("another wonderful day to be minimally truth-seeking")  
**Solution:** Rewrote all 25 test replies to be original but same vibe

### 3. Forced $GORK Mentions (21:49)
**Problem:** Security validation required every tweet to mention $GORK  
**Solution:** Removed Layer 5 validation check (lines 95-98 in security.ts)

### 4. Duplicate Replies (22:31 - 22:40)
**Problem:** Bot replying to same tweets multiple times across restarts  
**Root cause:** `lastMentionId` was in-memory only, reset on restart  
**Solution:** Created `state-manager.ts` with persistent `.bot-state.json`  
**Implementation:**
- Tracks tweet IDs we've replied to (not users)
- Saves to disk after every reply
- Loads on startup
- Keeps last 1000 entries

## Lessons Learned

1. **Verify model names immediately** - Don't assume, test all options upfront
2. **Persistent state is critical** - In-memory tracking fails across restarts
3. **Track tweets, not users** - One reply per tweet, not per person
4. **Original content > copied vibe** - Inspiration is fine, plagiarism is not
5. **Test with real API early** - Random test replies hide integration issues
6. **State file structure matters** - Changed from `processedMentions[]` → `repliedToTweets[]` broke compatibility
